01 / Orientation

The question is readout, not inner feeling

This experiment asks whether a coarse 27-channel affective/control state can be read from Qwen 3.5 9B’s residual stream. It does not claim that the model has 27 semantic feelings, a human-like affect system, or a validated control state.

The 27 channels are a model-derived latent projection. They are useful because they give a compact vocabulary for testing readout, gating, and later steering. They are not direct measurements of experience.

What the result supports

A coarse 27-channel projection is readable at mid-depth, and it survives 8-bit weight loading well enough to recalibrate. The result does not yet establish that the projection is a causal control state or that steering will work.

02 / Method

Mean-pooled residual states and per-channel ridge probes

The first readout used 864 contrastive rows, 32 per channel, split into 675 train and 189 held-out rows. Each row has a coarse target: 0.0 absent, 0.5 moderate/mixed, or 1.0 strong. These are hand-crafted calibration anchors, not measured ground truth.

For each prompt, the experiment extracts the mean-pooled hidden state at decoder layers 10–28. It trains one ridge probe per channel and reports held-out R², MAE, confusion, perspective sensitivity, probe cosine, and centroid distance.

The 8-bit run uses bitsandbytes with load_in_8bit=True. Its matmul path casts BF16 activations to FP16, so the run is best described as 8-bit weights + FP16 compute, not BF16 compute.

03 / Readout result

Readout peaks around layer 14, then weakens

Both BF16 and 8-bit runs peak at layer 14. BF16 reaches mean held-out R² ≈ 0.865; 8-bit reaches ≈ 0.864. The coarse error rate is about 12% for BF16 and 11.6% for 8-bit. Most errors are the expected 1.0 → 0.5 under-reading, not random channel collapse.

05 / 8-bit transfer

8-bit is close for readout, but shifts gate and intensity layers

The 8-bit readout is almost identical to BF16. The gate and intensity calibrations are more backend-sensitive: the best gate layer moves from 23 to 19, and the best intensity layer also moves from 23 to 19.

06 / Gates and intensity

Binary activation and continuous intensity are separate problems

The gate calibration uses an FPR cap as the primary criterion, with Youden’s J as a diagnostic. The intensity calibration keeps the gate decision and then fits a linear mapping on active rows. This avoids treating a deadzone threshold as an intensity estimate.

07 / Q6 placeholder

Q6 is downloaded, but not yet a result

Pending Q6 readout, gate, and intensity have not been run.

The Q6_K checkpoint is present at models/qwen3.5-base-q6/Qwen3.5-9B-Base.Q6_K.gguf, but the GPU was occupied. This section is a placeholder, not evidence.

Native Transformers GGUF Q6 is dequantized on this Linux GPU because no x86_64 CUDA GGUF matmul kernel is published. The run would be Q6 weights + dequantized FP16/FP32 compute, not true Q6 matmul.

True Q6 inference requires llama.cpp or a custom low-bit backend, and layer readout there is not plug-and-play. For the current Python readout path, the practical comparison is BF16 versus bitsandbytes 8-bit; Q6 is a later stress test.

08 / Limits

Readout is not steering, and labels are coarse

The calibration labels are hand-crafted anchors, not measured ground truth. The 27 channels are a projection vocabulary, not a claim that the model experiences those states. The readout is mean-pooled and layer-specific; last-token pooling, cross-validation, and lexical controls are still needed.

The most important limit is causal: read-best is not steer-best. A layer that predicts a channel well may not be the layer where activation addition changes behavior coherently. Steering must be tested separately with random-direction controls, dose-response, reversibility, and safety checks.

Backend sensitivity is also real: 8-bit readout is close to BF16, but gate and intensity best layers shift. Thresholds should not be copied across backends.

09 / Next steps

Run Q6, then move to bounded steering

The next practical sequence is:

  1. Run Q6-dequantized readout, gate, and intensity when the GPU is free.
  2. Compare Q6 against BF16 and 8-bit; recalibrate if transfer degrades.
  3. Choose the production backend: BF16 for reference, 8-bit for deployment, Q6 only if acceptable.
  4. Start experiments/steering/v1/ with activation addition, random-direction controls, dose-response, reversibility, coherence, and safety checks.

Steering is a separate phase. It should not be inferred from readout accuracy.
